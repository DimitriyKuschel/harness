# Harness — AI Team

[English](README.md)

Расширение VS Code: командный чат, в котором Claude Code, Codex и Antigravity (Gemini) работают над вашим проектом как одна команда, а вы — CEO. Вдали от компьютера за командой можно следить и управлять ею из Telegram.

Работает **через официальные CLI на ваших подписках**: расширение запускает `claude -p`, `codex exec` и `agy -p` как дочерние процессы. Токены не извлекаются, API-ключи не нужны.

## Что умеет

- **Роутинг.** Без @упоминания дешёвая модель (Haiku / Luna / Flash на low effort) оценивает задачу: сложность (`trivial → critical`), область (код, фронтенд, дизайн, маркетинг…) и нужна ли вся команда. Исполнителя выбирает не классификатор, а правила: порядок агентов для области (`harness.routing.affinity`) и израсходованная квота. Каждые 60% израсходованного лимита перевешивают одну ступень предпочтения, поэтому работа распределяется по всем подпискам. Агента, у которого почти кончился лимит, роутер обходит.
- **Команда.** Режим «Команда» (или «Авто», если классификатор решил, что работа крупная, или CEO просит распределить роли): лид составляет план из 2–6 задач и назначает их по сильным сторонам. Задачи разных агентов идут параллельно, задачи одного агента — по очереди, зависимости — первыми. В конце лид проверяет результат по критериям готовности и выносит вердикт: цель достигнута, нужна ещё итерация или нужно решение CEO. Ход плана виден в карточке задач.
- **Автопилот** (переключатель рядом с режимом, включён по умолчанию). Если лид решил, что нужна ещё итерация, он сразу планирует её, и команда продолжает без CEO, пока цель не достигнута. Автопилот останавливается, когда лиду нужно решение CEO, когда исчерпан лимит итераций (`harness.team.maxIterations`, по умолчанию 5), когда ни одна задача итерации не удалась, когда у всех агентов почти кончились лимиты или когда CEO написал новое сообщение. Кнопка «Ещё итерация» под проверкой лида продолжает работу вручную.
- **@упоминания.** `@claude`, `@codex`, `@gemini` (или `@клод`, `@кодекс`, `@джемини`) обращаются к агенту напрямую. Несколько упоминаний — агенты отвечают параллельно. `@all` / `@все` запускает брейншторм.
- **Брейншторм.** Все агенты отвечают независимо, модератор сводит консенсус, расхождения, рекомендацию и вопросы к CEO. Кнопка «Ещё раунд»: каждый критикует ответы коллег, затем новая сводка.
- **Кросс-ревью.** «Ревью» отдаёт ответ на проверку агенту *другого* вендора (только чтение). «Исправить» возвращает замечания автору.
- **«Сильнее».** Перезапускает задачу у того же агента на уровень сложнее: сильнее модель и больше reasoning.
- **Общий контекст.** У каждого агента своя нативная сессия. Перед каждым ходом агент получает только те сообщения чата, которые он ещё не видел.
- **Лимиты подписок.** Карточки агентов в шапке показывают, сколько **осталось** в 5-часовом и недельном окне; в подсказке — время сброса. Данные берутся у самих CLI без вызова модели: `claude -p /usage`, `codex app-server` (`account/rateLimits/read`), `agy -p /usage` (группа моделей Gemini). Обновляются при запуске, раз в 5 минут, после работы агента и по клику на карточку. У тарифа Codex Pro нет 5-часового окна — там «∞».
- **Кончился лимит — работу берёт коллега.** Если запуск упал с ошибкой исчерпанной квоты («Individual quota reached… Resets in 163h…», «You've hit your usage limit…», «5-hour limit reached ∙ resets 3pm»), агент помечается как исчерпавший лимит до времени сброса из сообщения — даже если `/usage` его CLI показывает, что лимит ещё есть. Его задачи из плана, ответ роутера, план и проверка лида, ревью и сводка сразу переходят к коллеге с лимитом; новому исполнителю сообщают, что предшественник мог успеть часть работы. Брейншторм идёт без него, роутер его обходит. На упавшем сообщении вместо «Повторить» — «Передать другому». Если лимит вернулся раньше (сменили тариф), в меню карточки агента есть «Лимит снова есть».
- **Модель по выбору CEO.** Клик по карточке агента открывает меню: «Авто» (модель по сложности задачи из `harness.models`) или конкретная модель — она закрепляется за агентом для всех запусков. Список берётся у CLI (`agy models`, кэш моделей Codex, алиасы Claude). Агенты знают об этом и подсказывают CEO, где сменить модель; лид может указать модель для отдельной задачи плана, если CEO её назвал.
- **Telegram.** Следите за командой и управляйте ею с телефона — см. раздел ниже.
- **Профиль расхода:** Эко / Баланс / Макс сдвигает уровень моделей вниз или вверх.
- **Доступ:** Только чтение / Правки / Полный доступ (см. таблицу ниже).
- **Очередь.** Сообщения, отправленные пока команда работает, выполняются по порядку.
- **Языки.** Русский и английский: интерфейс и инструкции агентам следуют настройке `harness.language`.
- Ссылки на файлы вида `src/app.ts:42` в ответах кликабельны. История чатов хранится отдельно для каждого workspace.

## Установка

Установите **Harness — AI Team** из панели Extensions: расширение есть в VS Code Marketplace и в Open VSX (Cursor, Windsurf, Antigravity, VSCodium).

Нужны установленные и залогиненные CLI: `claude`, `codex`, `agy` (Antigravity CLI). Подойдёт любой набор: команда собирается из найденных агентов. Расширение ищет их в `PATH` и в `~/.local/bin`; путь можно задать в настройках `harness.agents.*.path`.

Сборка из исходников:

```bash
npm install
npm run package          # → harness.vsix
code --install-extension harness.vsix
```

Разработка: `npm run watch` и F5 (Extension Development Host). Превью UI без VS Code: `python3 -m http.server` в корне и откройте `preview/index.html` (`?theme=light`, `?empty=1`, `?team=1`, `?quota=1`, `?menu=gemini`, `?untrusted=1`, `?lang=en`).

## Telegram

Работа команды дублируется в ваш Telegram, а задачи и команды можно отправлять оттуда — как из чата плагина.

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте токен.
2. В VS Code: **Harness: Подключить Telegram** (или значок телефона в шапке чата) → вставьте токен. Он хранится в защищённом хранилище VS Code (SecretStorage).
3. Нажмите «Открыть Telegram» → «Запустить» у бота. Ссылка несёт одноразовый код и действует 10 минут; бот привязывается к вашему личному чату и больше никому не отвечает.

Что приходит в Telegram: ваши сообщения из VS Code, готовые ответы агентов (длинные задачи и брейншторм — превью с кнопкой «Полностью»), план с ходом задач, проверка лида с вердиктом, уведомления. Пока команда работает, внизу висит сообщение «кто чем занят» с кнопкой «Стоп».

Что можно делать из Telegram:

- писать задачи, в том числе с `@claude`, `@codex`, `@gemini`, `@all`; ответ (reply) на сообщение агента продолжает разговор с ним;
- кнопки под ответами — как в плагине: «Повторить» / «Передать другому», «Ревью», «Исправить», «Ещё итерация», «Ещё раунд», «Сильнее»;
- `/status` — команда, лимиты, настройки; `/stop`; `/new`; `/chats`;
- `/mode`, `/profile`, `/access` (полный доступ — с подтверждением), `/autopilot`;
- `/model gemini gemini-3.8-flash-high`, `/model gemini auto` — закрепить или снять модель.

Бот работает, пока открыт VS Code: опрос идёт из расширения (long polling), публичный адрес не нужен. Сообщения, пришедшие, пока VS Code был закрыт, не выполняются. Если открыто несколько окон, бота обслуживает одно (в `/status` видно какое); переключить — **Harness: Подключить Telegram** → «Обслуживать Telegram из этого окна». В ограниченном режиме бот показывает чат, но агентов не запускает.

## Режимы доступа

| | Claude Code | Codex | Antigravity |
|---|---|---|---|
| Только чтение | `dontAsk` + allowlist (Read/Grep/Glob, git status/diff/log, ls, find…) | `sandbox_mode=read-only` + `approval_policy=never` | `--mode plan` (shell запрещён) |
| Правки | `--permission-mode auto` | `workspace-write` + сеть | `--dangerously-skip-permissions --sandbox` |
| Полный доступ | `bypassPermissions` | `danger-full-access` | `--dangerously-skip-permissions` |

У Codex в режиме «только чтение» запросы на выход из песочницы отключены. Иначе при `approvals_reviewer = "auto_review"` в `~/.codex/config.toml` такой запрос одобряется автоматически, и команда пишет файлы.

Брейншторм, раунды обсуждения, ревью и составление плана всегда работают в режиме «только чтение». Задачи плана выполняются с выбранным уровнем доступа.

В ограниченном режиме VS Code (Restricted Mode) чат открывается, но агенты не запускаются, пока папке не доверяют.

## Настройки

- `harness.language` — язык интерфейса и инструкций агентам: `auto` (как язык VS Code: русский для русского, иначе английский), `en` или `ru`.
- `harness.models` — модель и effort для каждого уровня сложности у каждого агента.
- `harness.routing.affinity` — порядок предпочтения агентов по областям.
- `harness.team.maxIterations` — сколько итераций автопилот может пройти без CEO.
- `harness.routing.classifier` — `llm` (точнее, один дешёвый вызов на сообщение) или `heuristic` (без вызова).
- `harness.strengths` — сильные стороны агентов: их видят классификатор и лид при распределении задач. Для агентов, которых нет в настройке, берётся встроенное описание на языке интерфейса.
- `harness.telegram.enabled` — дублировать чат в подключённый Telegram-бот и принимать оттуда задачи.
- `harness.telegram.apiUrl` — сервер Bot API (только в пользовательских настройках: туда уходит токен). Меняйте лишь на свой сервер Bot API или доверенный прокси.

## Известные ограничения

- Остаток Claude читается из текста `/usage` (структурированного вывода у команды нет). Если формат текста изменится, останутся данные из потока (`rate_limit_event`).
- Подтверждения действий в UI нет: режим доступа задаётся заранее.
- Параллельные задачи команды работают в одном рабочем дереве. Лид разводит их по непересекающимся зонам (папкам), но строгой изоляции нет. Исполнение в git worktree запланировано.

## Структура

```
src/core/          без зависимостей от VS Code
  agents/          адаптеры CLI → общий поток событий
  prompts/         инструкции агентам (en, ru)
  router.ts        оценка задачи, выбор агента/модели/effort, учёт квот
  quota.ts         распознавание ошибок исчерпанной квоты и времени сброса
  orchestrator.ts  чат, контекст, брейншторм, командная работа, ревью, исправления
  plan.ts          разбор плана лида (блок team-plan)
src/i18n/          строки интерфейса (en, ru), общие для хоста и webview
src/host/          контроллер расширения, хранение чатов, webview
  telegram/        бот: Bot API, зеркало чата и команды, привязка чата, выбор окна
src/webview/       React-интерфейс чата
src/test/          юнит-тесты (npm test) и ручные smoke-скрипты по реальным CLI
```
